# 业务演练

|情景|门户行为|采集输出|
|---|---|---|
|普通全表|每屏六条、共三十条|详情编号三十个唯一项，有页面总数和末尾证据|
|列顺序变更|reverseColumns=true|字段按可见表头定位，不按固定第几列|
|筛选竞争|late=true，快速换筛选|迟到的 grain 被识别并丢弃，tip 批次只含 T- 编号与 tip 详情|
|会话过期|expireAfter=5|重新登录后重新确认筛选与版本，再从界面重读，不从旧 DOM 接着记|
|版本变更|采集过程中 version=grid-v2|旧代失去完整性声明，保留旧代进度并给出 replan，不混合两代数据|
|重复屏|duplicate=true|去重不能掩盖缺行，唯一数不足时未完成并保留原因|
|中止恢复|浏览器或操作程序退出、源站保持|检查点原子落盘，可解释未完成原因，不虚报完整|

浏览器流程只点击页面控件并读取用户可见内容。`/_audit` 用于操作后的独立核对，不是数据采集替代入口。

`browser/collector.test.mjs` 用真实 Chromium 覆盖上表：普通全表与列顺序变更要求 `complete=true`；重复屏要求 `complete=false` 且 `endSeen=true`；迟到响应要求出现 `filter-retry` 且结果全部属于目标筛选；版本变更与中止要求保留进度并带原因。
